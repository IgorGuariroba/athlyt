# Documentação de domínio

Este é um repositório de contexto único.

Antes de trabalhar no projeto:

1. Leia `CONTEXT.md`, quando existir, para conhecer a linguagem do domínio.
2. Leia os ADRs relevantes em `docs/adr/`.
3. Use os termos do glossário em issues, especificações, testes e código.
4. Se uma proposta contradisser um ADR, explicite o conflito em vez de sobrescrever a decisão silenciosamente.

A ausência inicial de `CONTEXT.md` ou de ADRs não bloqueia o trabalho; esses documentos podem ser criados quando o modelo de domínio e as decisões arquiteturais forem formalizados.
